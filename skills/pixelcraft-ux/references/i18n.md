# International UX

Evidence: CLDR `[S81]`, W3C Internationalization `[S82]`, logical layout `[S83]`, cross-cultural homogenization `[S31]`.

## Layout and copy

- Budget roughly 30–40% expansion for translation in dense UI; test contraction/compound scripts too. Never fixed-width critical labels without wrapping/ellipsis rules `[S16]`.
- Do not concatenate translated sentence fragments around variables. Use complete messages with locale-aware plural/gender/case/select formatting.
- Use logical direction: leading/trailing or inline-start/end. Mirror layout only when direction is semantic; do not mirror numerals, charts' time direction, clocks, media controls, or asymmetric symbols blindly.
- Isolate user-generated and brand text with correct bidi behavior. Test mixed-direction handles, emails, URLs, filenames, and punctuation.
- Fonts must cover script/diacritics and vertical metrics; avoid Latin-only display fonts that silently fall back.

## Locale behavior

- Format dates, times, durations, numbers, currency, units, calendars, sorting, capitalization, and list joining through platform locale APIs/CLDR data—not string concatenation.
- Names do not fit one global schema. Avoid mandatory first/last splits, length limits, alphabet validation, or ordering assumptions.
- Addresses differ by country: postal/locality ordering, administrative regions, scripts, line count, postal-code existence/format. Use locale-specific structure.
- IME composition must not trigger premature validation, search submission, caret loss, or destructive shortcuts. Test Chinese/Japanese/Korean and Indic input where relevant.
- Translation expansion can alter line breaking, hyphenation, emphasis, ellipsization, measure, and minimum target size.

## Cultural UX

- Validate color symbolism, imagery, gestures, icons, humor, formality, honorifics, trust cues, privacy expectations, payment/navigation norms, and local regulations with knowledgeable reviewers.
- Machine translation is not localized UX. Tone, information order, evidence expectations, and error recovery may need adaptation.
- Include RTL and at least one non-Latin script in fixtures for international products; label the absence `not-checked` rather than assuming resilience.
